Stage2 crash (STATUS_STACK_OVERFLOW khi mở file, trong `unwrap_err`) đã được fix qua **3 nhóm bug độc lập**, tìm bằng bisection bin/t_a..t_k (native self-link). Trạng thái: t_a..t_k=0, t_io=0, t_b=0, t_b2=10 (đúng). Còn t_concat/t_read sai (pre-existing, xem cuối).

**BUG1 — ICONST 64-bit truncate.** `x86_selector.ax` OP_ICONST đọc `inst.src1 as i64` (chỉ 32 bit thấp). air_builder lower_int_lit emit hằng 64-bit qua `src1=val[31:0]`, `src2=val[63:32]`. Mask `0xfffffffffffffffe` bị cắt thành `0x00000000fffffffe` → xóa 32 bit cao con trỏ box → crash. **Fix:** `val = (src1 as i64) | ((src2 as i64) << 32)`; điều kiện XOR_ZERO check cả src2. Emitter x86_encoding.ax:36 `x86_encode_mov_ri` REX.W C7 sign-extend nên -2 vừa imm32.

**BUG2 — mono không transitive specialize → getfld stack overflow.** Generic method gọi method khác cùng type (unwrap→`self.is_ok()`) chỉ resolve đúng nếu callee được instantiate bởi lời gọi TRỰC TIẾP nơi khác; nếu không → lower thành OP_GET_FIELD + indirect call qua field rác → stack overflow. **Fix (tạm, an toàn):** inline tag-check trong std/result.ax `Result.unwrap`, `Result.unwrap_err`, `Option.unwrap` (không gọi is_ok/is_err/is_some). Fix gốc (mono substitute generic trong node_types/cast types) chưa làm.

**BUG3 — str (type 12, 16-byte {ptr,len}) unwrap trả len rác.** Chuỗi 4 lỗi:
- 3a: deref `ptr[str].*` đọc 8 byte. Fix air_builder lower_deref_expr: nếu node_types[child] là POINTER/REF extra==12 → type_id=12. Selector OP_DEREF hardcode `type_id==12 → type_size=16`.
- 3b: `regalloc_is_16byte` check `entries[type_id].size==16` cho OP_DEREF/OP_CALL — nhưng đôi khi deref type_id là generic. Hardcode `type_id==12 → return true` (str luôn 16-byte; size str=16 đã đúng ở typetable line 4456). Thêm nhánh OP_DEREF vào regalloc.
- 3c (lỗi chính): **OP_RETURN 16-byte load RAX trước RDX** (x86_selector.ax ~848). tmp_src_addr (base &value) có thể cấp vào RAX → load RAX=[base] clobber base → load RDX=[ptr+8] thay vì [&value+8] → len = nội dung chuỗi. **Fix: đảo load RDX trước, RAX sau.**

Bisection: t_d (is_ok/is_err) phân biệt tag-read; t_g/t_h (đọc raw[0]) phân biệt box-ptr vs payload; t_i (deref không mask) cô lập deref; t_b2 (str unwrap → len) là test cho BUG3.

**BUG3d (đã fix) — OP_CALL 16-byte result store clobber.** x86_selector.ax ~1103: `LEA tmp=&dest; STORE[tmp]=RAX; STORE[tmp+8]=RDX` — nếu tmp cấp vào RAX/RDX thì LEA clobber giá trị trả về. Đã sửa: MOV RAX→tmp_ret_lo, RDX→tmp_ret_hi TRƯỚC LEA, rồi store các temp. Sau fix: t_read hết crash (0xC0000005→exit 0).

**CONCAT/read_all blocker — ĐÃ FIX XONG (native str codegen).** Qua bisection phát hiện 3 bug ĐỘC LẬP (KHÔNG phải off-by-one như tưởng ban đầu):

**BUG-A — Param str (16-byte) aliasing.** 2 tham số `str` liền nhau: đọc tham số thứ 2 ra **giá trị tham số thứ 1** (vd `slen(a,b)->b.len` trả a.len). Gốc: regalloc bảo vệ param vreg khỏi giành arg-register của param SAU (x86_regalloc forbidden 535-542), nhưng chỉ kích hoạt qua `param_idx_of_vreg` set từ `MACH_MOV dst=VREG src=PHYS(argreg)`. Param 8-byte vật hoá bằng MOV đó → được bảo vệ. Param 16-byte (str) vật hoá bằng `LOAD/LEA/STORE` với scratch temp → KHÔNG tag → temp giành RDX (con trỏ param sau) → clobber. `(i64,str)` và param thứ 3 sống sót nên dễ tưởng off-by-one. **Fix: `emit_param_prologue` (x86_selector.ax) — vào đầu hàm snapshot TẤT CẢ arg-register int bằng `MOV snap=argreg` (được tag/bảo vệ, không clobber nhau) TRƯỚC, rồi mới nạp giá trị từ snapshot; set `param_idx_processed=nparams` để tắt lazy materialization.**

**BUG-B — concat bind nhầm DLL (sai ABI).** `std.string.concat` body = `@compiler_intrinsic("str_concat")` mà native air_builder KHÔNG xử lý (chỉ cgen/C-backend map). x86_coff `resolve_binary_sym_name` redirect `std.string.concat`→`ax_str_concat` (import từ ax_runtime.dll, ABI C/Win64: arg by-ref, return 16-byte qua hidden-pointer RCX) — KHÔNG khớp ABI value của AXIOM (str arg by-pointer, return RAX:RDX). Bản AXIOM value-ABI `ax_str_concat` trong runtime.ax bị **DCE** (redirect là post-AIR nên không có caller mức AIR). Triệu chứng: concat trả 10 cố định mọi input (đọc RAX=ptr, RDX=rác). **Fix: cho `concat` (std/string.ax) THÂN HÀM AXIOM thật (inline malloc/@memcpy/`buf as str`, khai báo `extern "C" fn malloc`); BỎ redirect concat ở x86_coff (call vào thẳng thân thật, value-ABI).** Confirm bằng `objdump -x`: import `ax_str_concat` biến mất.

**BUG-C — call-result 16-byte không nhận diện khi callee thiếu signature.** `regalloc_is_16byte` cho direct call tra ret-type từ symbol callee; với symbol stub/redirect (ret 0) → fail → chỉ capture RAX (mất len half). **Fix (phòng thủ, giữ lại): fallback trong regalloc_is_16byte — nếu không xác định được ret, quét forward tìm `COPY/MOVE src1==call_dest` có type 16-byte (vd `%4:t12 = copy %3`) → return true.**

`read_all` (std/io.ax) dùng `result_str + chunk` (toán tử `+` str — native lower thành OP_IADD integer-add, KHÔNG concat) → rỗng/crash. **Fix: `import std.string`; đổi thành `std.string.concat(result_str, chunk)`.** (Đã REVERT hack OP_IADD-str→ax_str_concat và pseudo-sym -23 — không cần nữa; str `+` native vẫn chưa hỗ trợ, dùng concat thay thế.)

**BUG-D (ROOT CAUSE stage2 self-compile crash 0xC0000005) — `regalloc_is_16byte` đệ quy sai trên OP_CAST.** Code cũ gộp `OP_COPY|OP_MOVE|OP_CAST`: khi dest-type ≠16-byte thì **đệ quy xuống src1**. Cast `str→ptr` (`s as ptr[u8]`): dest=`ptr`(8B) nhưng đệ quy xuống src=`str`(16B) → return true → con trỏ 8-byte bị phân loại NHẦM 16-byte → cấp 2 spill slot → mọi lần dùng sau (`sp as i64`, truyền tham số) đọc lệch slot/không ổn định. Triệu chứng cô lập: `(sp as i64) != (sp as i64)` = **true** (cùng expr, 2 giá trị). `sp[0]` (OP_INDEX) tình cờ đọc slot thấp đúng nên các test index đơn giản qua được → khó thấy. Trong stage2: `check_prefix(prefix as ptr[u8])` + `s as ptr[u8]` (is_verbose_debug/print path) sinh mã hỏng → crash NGAY trước print "[Debug] Stage 1" (log 0 byte). **Fix: tách `OP_CAST` riêng khỏi COPY/MOVE — cast ĐỔI kiểu nên tính size CHỈ theo dest type_id (12 hoặc size==16 → true, else false), KHÔNG đệ quy src1.** (x86_selector.ax ~422). COPY/MOVE giữ đệ quy (bảo toàn kiểu).

Chẩn đoán bằng marker AXDBG-M1..M6 +fflush chèn vào main (tmp_concatenated_air.ax): cả 6 marker in → crash sau M6 tại print "[Debug] Stage". is_verbose_debug lọc "[Debug] Stage"→false (vẫn in), usage strings bắt đầu space/chữ nên không đi path '['→check_prefix; "[Debug] Stage" là string ĐẦU TIÊN đi path đó → lộ bug cast. Markers tự bị xoá khi rebuild_stage1 regen concatenated.

Sau BUG-D: stage2 vượt crash cũ, đọc 7 stdlib + strip + concatenate, nhưng crash ở memcpy đầu trong `concatenate_stdlib` → lộ BUG-E.

**BUG-E (ROOT CAUSE #2) — spill-all fallback cấp 1 slot cho vreg 16-byte.** x86_regalloc.ax ~407-415: hàm LỚN (`intervals>50000` hoặc `insts_len>5000`, vd concatenate_stdlib/main/nhiều hàm compiler) rơi vào nhánh "spill-all fallback" cấp **mỗi vreg đúng 1 slot 8-byte** (`spill_count_s+1`) — kể cả str 16-byte. → mỗi str spill (16B) ĐÈ slot vreg kế → `res_src` bị `new_buf=@alloc()` ghi đè → ptr hỏng → memcpy crash. Hàm NHỎ dùng nhánh graph-coloring (đã cấp đúng 2 slot 16-byte, dòng ~586-588) nên test nhỏ (t_concatmem 8-way memcpy=83 ✓) chạy được; chỉ hàm lớn lộ bug → KHÓ reproduce, phải pin bằng markers trong build stage2 thật. **Fix: trong fallback, `if regalloc_is_16byte(sv,fn_ptr,table,symbols): spill_count_s+2 else +1` (khớp graph-coloring).** Chẩn đoán: markers AXDBG-C1..C6/D1..D6 trong concatenate_stdlib → C3(alloc-done) in, D1(sau memcpy res_src) KHÔNG → crash tại memcpy đầu; len(res_src) ở C1 đúng nhưng res_src as ptr[u8] ở memcpy hỏng → slot bị @alloc/new_buf clobber.

**BUG-F (root cause crash concatenate_stdlib) — std.string intrinsics KHÔNG lower native.** Sau BUG-E vẫn crash tại memcpy đầu trong concatenate_stdlib. Dùng **gdb** (msys64 `C:\msys64\ucrt64\bin\gdb.exe`): crash trong `ucrtbase!memmove` tại `mov (%rdx),%r8` với **rdx=0 (src=NULL)** → @memcpy gọi với con trỏ nguồn NULL → `res_src.ptr` NULL. res_src = strip_package_prefixes(...) dùng `std.string.replace`. **replace là `@compiler_intrinsic("str_replace")`** — native air_builder (lower_call_expr ~860) CHỈ lower 6 intrinsic OS (is_windows/is_linux/is_macos/os_name/arch_name/path_separator → const); MỌI str intrinsic khác (str_replace/str_slice/str_contains/str_starts_with/str_ends_with/str_index_of/trim/split...) KHÔNG được lower → trả str rác (ptr=NULL, len rác). Hoạt động dưới C-backend (stage1 build OK) nên chỉ lộ ở native self-link. Reproduce: t_replace2 → replace trả ptr=NULL cho cả pattern-absent. **Fix: viết thân AXIOM value-ABI thật cho replace/slice/index_of/contains/starts_with/ends_with trong std/string.ax** (dùng .ptr/.len/malloc/@memcpy/index byte — pattern giống concat đã fix). Native build-path dùng: slice 17×, contains 10×, ends_with 7×, starts_with 6×, replace 46×. Test cô lập t_strfns=0 (all pass). index_of/trim/split/to_upper/... = 0 lần trên native path (chưa cần). cgen.ax/fmt.ax dùng slice nhiều nhưng là C-backend/formatter (ngoài native path).
