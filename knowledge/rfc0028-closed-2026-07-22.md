User directive 2026-07-22: "thực hiện dứt điểm b3" (= RFC 0028 jump-table, the last open
item being if-chain recognition + the default-on product decision). **RFC 0028 is now CLOSED.**

Baseline **481/481 → 485/485**, driver `57738F36C9A0F262` (was `4043C7B942EBB203`), A==B.

## What shipped

`try_lower_if_chain_bsearch` + `ifchain_collect_values` + `ifchain_const_int` +
`emit_bsearch_blocks` in `bootstrap/stage1/air_builder.ax`, wired into `lower_if`, behind the
existing opt-in `-jumptable`. Recognizes `if x == C0: … elif x == C1: … else:` over one integer
variable → balanced O(log N) compare tree. Beyond what the `match` path does:

- **disjunctive arms** `x == A or x == B` (several values → ONE block, body lowered once —
  this is why it needed `emit_bsearch_blocks`, whose leaves JUMP, rather than reusing
  `emit_bsearch_range`, which lowers a body inline at each leaf and would clone it per value)
- **named consts** as compare values (`op == OP_IADD`) via SYM_CONST initializer folding
- **unsigned scrutinees**, sorted unsigned to match the `CC_B` `select_comparison` emits
- threshold **8** values (not `match`'s 4) — a tree costs ~3 blocks + 4 vregs per value

Oracle `t_ifchainjt` (exit 53): named consts, mixed-sign, u16 chain incl. `0xF000` (a signed
sort would mis-order it), gap/below-min/above-max → else, no-else chain, 3-arm chain that must
stay linear, or'd arms with a local-declaring shared body, and an `and`-guarded last clause that
must force the WHOLE chain back to linear. Registered both linear and `-jumptable` × O0/O1/O2.

## The decision (this was the actual deliverable)

**`-jumptable` stays OPT-IN. Measured, not deferred.**

| Workload | Linear | Tree | |
|---|---|---|---|
| 32-arm dense `match`, 20M dispatches -O2 | 255 ms | 184 ms | 1.38x |
| 32-arm `if/elif` chain, 20M dispatches -O2 | 255 ms | 174 ms | **1.47x** |
| compiler self-build | 7.00 s | 7.06 s | **−0.8%, no win** |

RFC 0028 §7e had speculated if-chain recognition "WOULD speed the compiler's own hot dispatch."
**It does not.** The compiler's longest chains interleave `and`-guarded clauses
(`if inst.opcode == OP_CALL and inst.src1 == 0`) that disqualify the whole chain, and self-build
time is not dispatch-bound anyway. Default-on would cost +0.5% code size (2 523 136 → 2 534 912)
on every build for zero compiler benefit; programs that benefit can pass the flag. **Also kills
the §3–§7c O(1) `.rodata`+reloc jump-table** — the log factor is demonstrably not the limit, so
that large linker/opcode surface is not worth building.

Self-host safety proven: a compiler built WITH `-jumptable` emits **byte-identical output** to
one built without (`57738F36C9A0F262` both ways).

## Two bugs — both invisible to the test suite

1. **The rewrite silently never fired.** Pass 1 reused ONE `scratch` buffer across clauses, so
   by pass 2 it held the LAST clause's values; slot 0 got the final arm's value, collided with
   that arm's own entry, and the duplicate guard rejected every chain. **Every oracle still
   passed** — falling back to linear is always correct. Only `linear_hash != jumptable_hash`
   exposed it. ⚠️ **An optimization whose tests pass has not necessarily RUN. Assert that it
   changed the output.** Cost: ~6 instrumented rebuilds to find.
2. **Bailing after allocating leaked basic blocks.** The dup guard returned false *after*
   `fb.new_block()` had minted one block per clause; abandoned blocks live in the function
   forever. Combined with bug 1 (nearly every chain bailed) this leaked thousands of dead blocks
   and blew the allocator's **256MB ceiling** (`SEGMENT_SIZE 65536 * MAX_SEGMENTS 4096`,
   std/mem/alloc.ax) → OOM at func ~950/983 of the self-build. **I first misread this as "trees
   are inherently too expensive" and nearly shipped a raised threshold as the fix** — the OOM
   vanished entirely once blocks were minted only after every bail check. ⚠️ **Never allocate
   into the function until the rewrite is committed.**

⚠️ Also re-learned (the [[backlog-group-a-closed-2026-07-22]] lesson, verbatim repeat): a
`sed`-based trace-strip left an **orphaned `if` with no body** → parse error. Deleting a
trace line that was the sole body of an `if` breaks the suite.

## Useful facts banked

- Compiler heap ceiling = **256MB** (`SEGMENT_SIZE * MAX_SEGMENTS`); the self-build runs close
  enough to it that a per-function leak is fatal. Relevant to any future pass that allocates
  per-node structures.
- `select_comparison` (x86_selector.ax:768) already picks signed CC_L vs unsigned CC_B from the
  operand's register type, so unsigned compare trees need only a matching unsigned SORT.
- `ax_printf_local` takes **8 i64 args** — always pad. Unbracketed debug prefixes only
  (`is_verbose_debug` suppresses `[D`/`[M`/`[T`/`[C`/`[f`).
